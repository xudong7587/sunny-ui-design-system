# Sunny UI Design

先识别当前产品的页面结构、共享组件和已有样式约束。沿用它们，按内容决定版式。用户当前要求优先于参考规范。

1. 读取 [设计规范](references/design-standard.md)。接入代码时再读 [集成说明](references/integration.md)。
2. 色彩、材质、明暗分别建模；复用 `assets/appearance/` 的组件与 CSS，或把同一变量合同映射到现有框架。不要把整个项目重写成示例布局。
3. 给外层面板使用 `.appearance-surface`、内层卡片使用 `.appearance-surface-inner`、控件使用 `.appearance-control`、侧栏使用 `.appearance-sidebar`。宿主适配样式放在宿主项目，保持模块独立。
4. 玻璃要透光并有层次，纸页要温暖，渐层要有明确方向。每种材质都覆盖小卡片和控件。固定文字清晰度，状态色保持语义。
   柔软浮雕遵循外层凸起、内层凹陷、控件轻凸与按压凹陷；复用 soft 令牌，检查深色柔光、选中、错误、禁用和键盘焦点。提示、导航和工具栏按文档流分开，不使用负间距互相覆盖。
5. 多色预设用圆形 `conic-gradient` 色盘展示，主色要覆盖不同色相。选中态、焦点和按压反馈即时明确。
6. 在真实页面检查桌面、手机、浅深模式、刷新记忆、快速切换、长标题和长列表。具体视口和检查项见规范。使用缩减动效或透明度的用户仍要能看清和操作。

用户偏好：有质感、可组合、层次清晰；主题风格可以多样，以实际好看和可读为标准。以 SunnyUI 的规范和当前产品已确认的设计为依据。避免为了动效而增加动效，避免全局无差别重写。

质感设计不能只替换描边和阴影。先确定背景环境，再分别设计外层、内层和控件：浮雕应从同色基底连续隆起，玻璃应有可透入的背景与方向性折光，极光使用多色环境柔光，纸页、描边、双色和缎光各有独立的表面语言。具体方法与宿主 CSS 冲突处理见设计规范和接入说明。

交付时说明改动范围、运行方式、验证结果和限制。仅引用已完成的验收，不声称参考规范能保证任何项目自动达到相同效果。
